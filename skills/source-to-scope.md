# Skill Contract: Source Docs to Scope Baseline

## Purpose
Create `artifacts/scope-baseline.md` from discovery notes, proposals, solution material, and commercial context.

## When to use
Use when the project needs a first explicit in-scope and out-of-scope baseline.

## Primary methodology coverage
- 02-03 Scope definition
- 03-01 Current-state analysis
- 03-02 Solution design

## Required inputs
- discovery notes, workshop notes, or proposal material,
- plus at least one of: project charter, solution deck, architecture note, or milestone note.

## Output artifacts
- `artifacts/scope-baseline.md`
- suggested updates for the methodology execution log

## Required sections
Use the scope-baseline template and make these explicit:
- in scope,
- out of scope,
- constraints,
- dependencies,
- assumptions,
- acceptance approach,
- open questions.

## Validation checks
- included and excluded work are both explicit,
- dependencies are visible,
- major assumptions are visible,
- there is at least a first acceptance direction.

## Guardrails
- do not hide unresolved scope boundaries,
- do not pretend exclusions are agreed if they are only proposed,
- ask for more detail if the scope boundary is weak.
